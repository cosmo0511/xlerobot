---

## 1. 활동내용

### 1-1. 프로젝트 개요
저가형 오픈소스 로봇 팔 SO-101 두 대와 옴니휠 이동 베이스(LeKiwi)를 결합한 모바일 양팔 로봇(XLeRobot)을 구성하고, 사람이 내린 자연어 지시(예: "빨간 주사위를 집어 바구니에 넣어")를 로봇이 이해해 수행하도록 하는 것이 목표이다. 조작 정책으로는 Hugging Face LeRobot의 비전-언어-행동(VLA) 모델 SmolVLA를 사용하고, 사람이 원격조종(텔레옵)으로 시연한 데이터를 모방학습시키는 방식을 택하였다.

### 1-2. 시스템 설계 — 기기 3대 분산 구조 (Pi-A / Pi-B / PC)
로봇 위에 올라가는 라즈베리파이는 연산 능력이 부족하여 VLA 모델을 직접 돌릴 수 없으므로, 역할을 세 기기로 나누어 설계하였다.

| 기기 | 담당 하드웨어 | 역할 |
|---|---|---|
| **Pi-A** (양팔 라즈베리파이) | SO-101 팔로워 2대(USB 직결), 리더암 2대, 카메라 3~4대 | 팔 제어 노드(arm_node) — 30Hz 제어 루프를 로컬에서 실행 |
| **Pi-B** (베이스 라즈베리파이) | LeKiwi 옴니휠 베이스 + 라이다 | ROS2 / SLAM / Nav2 자율주행 스택 |
| **PC** (GPU) | — | SmolVLA 추론 서버, 명령 해석·작업 순서를 조율하는 에이전트 |

팔과 베이스를 서로 다른 라즈베리파이·시리얼 버스로 분리하여 두 장치가 동시에 움직여도 하드웨어 충돌이 없도록 하였고, 조율은 소프트웨어에서만 하도록 하였다.

**기기 간 통신 설계**
- PC ↔ Pi-A : LeRobot 비동기 추론(gRPC). Pi-A가 관측(카메라 영상 + 관절 12개)을 보내면 PC가 행동 50개 묶음(action chunk)을 돌려줌.
- PC ↔ Pi-B : ROS2 DDS의 `NavigateToPose` 액션으로 목표 위치 하나만 전달하고 도착/실패를 받음.
- PC ↔ Pi-A (명령) : ZMQ REQ/REP, JSON 한 줄 프로토콜 (`ping` / `park` / `run`).

**무선 대역폭 문제와 action chunk 방식**
로봇과 PC 사이가 Wi-Fi이기 때문에 카메라 영상을 매 프레임 보내면 약 80MB/s가 필요해 불가능하다. SmolVLA는 한 번 추론할 때 행동 50스텝을 묶어서 내놓으므로, 큐가 절반 이하로 줄 때만 새 관측을 보내도록 설계하면(약 0.8초에 한 번) 약 2MB/s로 충분하다. 또 30Hz 제어 루프가 Pi-A 안에서 돌기 때문에 네트워크가 잠깐 끊겨도 큐에 남은 행동을 계속 수행할 수 있다.

**작업 흐름(에이전트) 설계**
사용자 명령 → (LLM으로 태스크 분류) → 팔 파킹(주행 자세로 접기) → Nav2로 목표 책상까지 이동 → 안정화 대기 → SmolVLA로 집기/놓기 수행 의 순서로 실행되도록 설계하였다. 이동과 조작은 순차로만 실행하고(이동 중 팔을 쓰면 무게중심이 흔들림), 파킹에 실패하면 이동하지 않도록 하여 가구 충돌을 막았다.

**설정·안전 관련 설계**
- 태스크/위치 정의를 `config/tasks.yaml` 한 곳으로 모으고 프로그램 시작 시 검증 — 학습 라벨과 글자가 다른 지시문이 들어가 조용히 성능이 떨어지는 버그를 원천 차단.
- 카메라 설정을 `config/cameras.*.yaml` 하나로 통일하여 녹화와 추론이 같은 파일을 읽도록 함(카메라 이름이 어긋나면 정책이 아무 행동도 못 하는 문제 방지).
- 집기 후 그리퍼 상태를 확인하여 못 잡았으면 다음 단계로 넘어가지 않음.
- 하드웨어 없이 돌릴 수 있는 스모크 테스트 작성.

### 1-3. 원격조종(텔레옵) 시스템 구축
모방학습 데이터를 얻기 위해 사람이 로봇을 조종하는 텔레옵 환경을 구축하였다.
- LeRobot 0.6 소스를 직접 확장하여 양팔 로봇 클래스(`bi_so_follower`)에 **바퀴 3개와 호스트/클라이언트 통신**을 추가하였다. 로봇 쪽 라즈베리파이에서 호스트가 팔·바퀴·카메라를 열고, PC가 ZMQ로 접속하여 관측을 받고 행동을 보낸다.
- 조종 입력은 **리더암 2대(팔) + 키보드(바퀴)** 를 하나의 텔레옵 장치로 합쳐 15차원 행동(양팔 관절 12 + 이동 속도 x, y, 회전 3)을 만든다.
  - w/s/a/d 이동, z/x 회전, c/v 속도 변경. 오조작 방지를 위해 바퀴는 잠긴 상태로 시작하고 `g`를 눌러야 움직인다.
- 옴니휠 3개(240°/0°/120° 배치)의 역기구학으로 x·y·회전 속도를 각 바퀴 속도로 변환.
- 무선이 끊기면 호스트 워치독(500ms)이 바퀴를 자동 정지시키는 안전장치를 넣었다.
- 카메라 4대(상단·베이스·왼손목·오른손목)를 동시에 MJPG 640×480 30fps로 여는 것을 실측 확인(합계 약 26Mbps).
- 리더/팔로워 암 캘리브레이션을 완료하고 백업하였다.

### 1-4. (진행 중) 데이터 수집 및 학습
텔레옵으로 "1m 주행 후 지시한 색(빨강/노랑) 주사위를 해당 팔로 집어 바구니에 넣기" 시연 데이터를 수집하였다(104 에피소드, 약 66분). 언어 지시의 효과를 검증하기 위해 SmolVLA(언어 사용)와 ACT(언어 미사용 대조군)를 같은 조건(batch 16, 80k 스텝)으로 학습 중이다.

## 2. 활동계획 대비 변동 사항

| 항목 | 초기 계획 | 변경 | 이유 |
|---|---|---|---|
| 기기 구성 | Pi-A(양팔) + Pi-B(베이스) 라즈베리파이 2대 | 라즈베리파이 1대 — 바퀴 모터 3개를 오른팔 시리얼 버스에 연결 | 두 기기 간 시간 동기화·통신 부담을 줄이고, 텔레옵 녹화 시 팔과 바퀴를 하나의 관측/행동으로 기록하기 위함 |
| 주행 방식 | 라이다 + Nav2 자율주행으로 책상까지 이동 | 자율주행 미사용. 바퀴도 텔레옵으로 시연하고 정책이 직접 주행 속도를 출력 | 짧은 거리(1m) 태스크에서는 SLAM 지도·위치 보정 비용이 크고, 정책 하나로 주행+조작을 학습하는 쪽이 실험 목적에 맞음 |
| 태스크 | 책상 2개·주사위 3색 다단계 태스크 | 1m 주행 → 지시한 색(빨강/노랑) 주사위를 바구니에 (지시문 2종) | 기간 내 데이터 수집·평가가 가능한 규모로 축소, 언어 효과를 명확히 비교하기 위함 |

Pi-A/Pi-B 구조에서 설계한 action chunk 기반 통신, 설정 단일화, 안전 정지 등의 핵심 설계는 변경 후 구조에도 그대로 이어서 사용하고 있다.

## 5. 자기평가
실제 하드웨어를 대상으로 시스템을 설계하면서, 처음 세운 구조(Pi 2대 + 자율주행)가 실험 목적과 일정에 비해 과하다는 것을 직접 부딪히며 깨닫고 구조를 단순화하는 판단을 내릴 수 있었다. 특히 무선 대역폭, 카메라 장치 인식, 제어 주기 같은 문제는 시뮬레이션이나 이론으로는 드러나지 않는 부분이어서, 측정하고 원인을 찾아 고치는 과정에서 로봇 시스템 엔지니어링 역량이 크게 늘었다. 남은 기간에는 공정한 비교 실험을 설계·수행하여 VLA 모델에서 언어 정보가 실제로 어떤 기여를 하는지 정량적으로 검증하는 연구 역량을 기르고자 한다.
